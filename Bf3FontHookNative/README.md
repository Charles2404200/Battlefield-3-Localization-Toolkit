# BF3 Font Hook (C++ x86)

This is the native font loader for the [Battlefield 3 Vietnamese Localization Toolkit](../README.md). It builds an x86 `dinput8.dll` proxy for the tested 32-bit Steam release of Battlefield 3. The proxy forwards DirectInput 8 exports to the system DLL and uses MinHook to intercept font reads. It does not launch the game or modify CAS archives, `UI.toc`, or `cas.cat` on disk.

## Font files

Place the proxy and three fixed-size payloads in the game directory:

```text
Battlefield 3/
  dinput8.dll
  fonts/
    fontcollection_en_fontlib.cas-payload       62,403 bytes
    eulafontcollection_en_fontlib.cas-payload   28,727 bytes
    storefontcollection_en_fontlib.cas-payload  28,845 bytes
```

The payloads are generated by [`Bf3FontSubset`](../Bf3FontSubset/README.md) from edited GFX files containing Vietnamese glyphs and the `vietnamese_map.json` produced by `Bf3TextDump`. The loader checks their packed and decoded sizes and block structure. An invalid or missing payload is skipped. Font files are loaded at startup, so restart BF3 after changing them.

## Hook behavior

On each `ReadFile` request, the hook checks the expected CAS archive, exact offset, and payload length before replacing the returned bytes in memory. It also handles `GetOverlappedResult` for reads that finish asynchronously. The archive cache records volume, file index, and size for each handle, revalidates that identity on matching reads, and clears it when the handle closes. It does not retain game buffer pointers after a read; `VirtualQuery` and an exception guard check a destination before copying.

This follows BF3's observed CAS-loading route. It does not scan or patch unverified font asset pointers in the game's heap. Those structures have not been identified reliably for this build.

Runtime file logging is disabled. Older builds may have left `fonts/hook_native.log`; the current DLL does not append to it. A `fonts/probe_text.flag` can enable the existing text-conversion diagnostic hook internally, but with logging disabled it produces no log output.

## Build and smoke test

Build with CMake 3.20+ and Visual Studio C++ Win32 tools. Substitute the generator name for your installed Visual Studio version if necessary:

```powershell
cmake -S Bf3FontHookNative -B Bf3FontHookNative/build-x86 -G "Visual Studio 18 2026" -A Win32
cmake --build Bf3FontHookNative/build-x86 --config Release --target bf3_dinput8_proxy bf3_font_smoke
```

The DLL is written to `Bf3FontHookNative/build-x86/Release/dinput8.dll`. Run the x86 smoke test with a directory containing the three payload files:

```powershell
& Bf3FontHookNative/build-x86/Release/bf3_font_smoke.exe 'C:\Path\To\Battlefield 3\fonts'
```

The smoke test uses its own sparse CAS file. It checks synchronous reads, overlapped reads, and an incorrect offset; it does not start BF3. The [GUI](../Bf3VietHoaGui/README.md) installs the DLL with backups after building the text and font payloads.

MinHook v1.3.4 is vendored in `third_party/minhook`; see its `LICENSE.txt`.
